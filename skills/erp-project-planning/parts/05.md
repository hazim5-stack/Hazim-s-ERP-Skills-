Domain owners must approve executable scenarios.

Minimum ERP scenario family:
1. PO -> partial receipt -> quality -> supplier invoice -> payment.
2. Receipt before invoice using GRNI.
3. Invoice price variance after receipt.
4. Reservation collision under concurrency.
5. Partial manufacturing completion.
6. Material substitution in BOM.
7. Production scrap/rework.
8. Lot expiry and FEFO issue.
9. Quality rejection blocking shipment.
10. Sales return and cost reversal.
11. Closed-period backdating rejection.
12. Journal reversal preserving history.
13. Multi-currency invoice and settlement.
14. Cross-tenant access rejection.
15. Backup restore and ledger reconciliation.

# 42. AI/Vibe-Coding Guardrails

AI may accelerate implementation but must never invent domain semantics.

Mandatory rules:
- no feature solely because UI requests it,
- no silent fallback,
- no fake implementation behind selectable option,
- no float for money,
- no soft-delete for immutable ledger events,
- no business enum only in frontend,
- no cache as financial truth,
- no direct external side effect assumed atomic with DB,
- no generated permission list without SoD review.

AI must ask for or flag missing domain policy rather than guess.

# 46. Planning Completion Gate

Do not declare the project ready for implementation if any of these are undefined:
- inventory source of truth,
- accounting posting rules,
- valuation policy,
- period close,
- reversal model,
- authorization model,
- tenant isolation model if multi-tenant,
- transaction boundaries,
- idempotency model,
- backup/recovery objectives,
- acceptance tests for critical workflows.

Final verdict must be one of:
- READY FOR IMPLEMENTATION
- READY WITH DOMAIN DECISIONS PENDING
- NOT READY FOR IMPLEMENTATION

# 47. Final Principle

**Design the invariants before the interfaces.**

A production ERP is not a collection of screens. It is a controlled system of business events, ledgers, state transitions, permissions, reconciliations, and recovery rules that remain correct under concurrency, failure, and audit.
